# DT295 の TS が出ない／CC が飛ぶ原因（参考リポジトリの調査から）

最終確認: 2026-11-17

## 概要

`soralis0912/MB8AC031-Driver`（MIT）の `docs/tuning-dt295.md` に、
PIX-DT295 (`06b8:103b`) の実機で 1 つずつ効果を確認したレジスタ操作が記録されている。
その中に、私たちの「CS06 がロックしても TS が出ない」「`rc=7` / リング未達」の
症状と一致する原因が 2 つある。

なお、当該リポジトリは**独自ファームウェア MB8AC031-CFW** を使う
（`README.md`: 純正ファームウェアとは通信しない）。
私たちの pix-userland は純正ファームウェア前提なので、レジスタ番地は同じチップで
共通だが、効果が同一かは未確認。

## 原因 1: 地上側が TS の出力線を手放していない

`docs/tuning-dt295.md`「衛星（BS・CS110）」より:

> 地上の復調 `0x0E` の bit2〜0 を `111` に — 地上側が TS の出力線を手放す。
> どれかが 0 だと、ロックしても TS が出ない。地上波を選局するときに `001` に戻す

私たちの `src/dt295.c` の `sat_terrestrial_sleep()` は
`demod_write(0x25,0)`, `demod_write(0x23,0x4d)`, `demod_write(3,0x90)`,
`rf_write(0x12,0)`, `rf_write(0x0b,0)` を書くだけで、
**地上 demod `0x0E` の bit2〜0 を `111` にしていない**。

`demod_write(d, 0x0e, (v & 0x70) | 1)` はあるが、これは地上選局側の
`bit2〜0 = 001` の設定で、衛星へ切り替える際の `111` ではない。

したがって、地上选局の状態が残ったままだと、
衛星（CS06 を含む）がロックしても TS が出ない状態になりうる。

観測との対応:
- `state=0x10 (bootable)` / `locked=1` / `cn_mdb` 良好
- しかし `usb_bytes` は PSI 相当 (~80KB) で止まり、その後 `rc=7`
- 物理 USB リセット直後だけ一時的に回復する

## 原因 2: CS のヌルパケットが USB を詰まらせている

`docs/tuning-dt295.md`「衛星（BS・CS110）」より:

> 復調 `0x8E` = `0x02` — bit1 を 1 にするとダミーのスロットを落とす。
> 0（電源投入時）だと、CS のトランスポンダーはヌルパケットが 3 割を超え、
> USB のエンドポイントが受けきれずに連続性カウンタが飛ぶ。
> 1 にするとヌルは 1 割前後に減り、飛びが無くなる。TSID は同じ。BS は変わらない。

私たちの `src/dt295.c` には `sat_reg_write(d, 0x8e, ...)` が存在しない
（`grep` で確認）。したがって CS のヌルパケットが 3 割のままで、
USB エンドポイントが受けきれず CC が飛ぶ／リングに積まれたデータが
reader に届かない状態になりうる。

観測との対応:
- `usb_bytes` (completed) は伸びているのに `usb_delivered_bytes` が 0 のまま
- `usb_late_actual_bytes` が増える
- `rc=7` (LIBUSB_ERROR_TIMEOUT) が 10 秒で発火

## 未確認

- 純正ファームウェアで `0x0E=111` / `0x8E=0x02` が同じ効果を持つか
  （参考リポジトリは独自 CFW 前提）
- 私たちの `sat_wake()` / `sat_initialize()` がこれらのレジスタを
  別の経路で書いていないか（全文精査は未実施）
- 物理 USB リセット後に一時的に回復する现象と、这些レジスタの初期値の関係

## レジスタ試験の結果（2026-11-17）

参考リポジトリの知見を pure ファームの pix-userland に適用する試験を実施した。

- `sat_terrestrial_sleep()` に 地上 demod `0x0E` bit2〜0 = `111` を追加
- `sat_tune()` に 衛星 demod `0x8E = 0x02` を追加
- ビルド成功、デプロイして CS06 / GR T21 / CS08 を試験

結果: **いずれも `rc=7 bytes=0`**（`elapsed_ms=0`、選局フェーズで即失敗）。

切り分けのため変更を revert して元のコードで再試験したが、
**やはり全チャンネル `rc=7 bytes=0`** だった。したがって:

- レジスタ変更は原因ではない（revert しても直らない）
- デバイス自体が、USB リセット（`usbreset 06b8:103b`）でも回復しない
  状態に陥っている
- `state=0x0010 bootable` には戻るが、キャプチャは成功しない
- ファームウェアが内部的に固まっており、USB 再列挙だけではリセット
  されない状態と推定される

物理的な USB 抜き差し（電源を切って入れる）で一度回復したが、
その後また不安定になった。恒久的な解決にはハードウェア側の対応が必要。
